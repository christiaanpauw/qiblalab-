# ADR-06: Separation of raw source data from derived data

**Status**: Accepted
**Date**: 2026-07-13

## Context

The design doc requires that the raw imported data be kept distinct from cleaned and derived data, and that every cleaning decision be recorded in a machine-readable audit log. It also requires an immutable row identifier linking every derived observation to the original spreadsheet row.

There are two audiences for the data:
1. **Package users** who want a clean, analysis-ready dataset without downloading anything.
2. **Reproducibility auditors** who need to verify exactly what was changed from the source.

## Decision

Three-layer data architecture:

**Layer 1 — Raw source** (`data-raw/Mosques_Jan2021.xlsx`):
The original file from Figshare, never modified. Pinned by DOI and MD5. Version-controlled as a binary in the repo. Regenerated by `data-raw/qibla_data.R` if lost.

**Layer 2 — Cleaned package data** (`data/gibson_qibla.rda`):
The `gibson_qibla` data frame. Contains all original columns (renamed to snake_case) plus derived columns (`row_id`, `year_ce_min`, `year_ce_max`, `*_source` columns retaining pre-correction values). Carries `attr(., "provenance")` and `attr(., "audit_log")`. This is what users load with `data(gibson_qibla)`.

Permitted cleaning operations on Layer 2:
- Column renaming (with mapping documented in audit log)
- Case standardisation of categorical values (logged)
- Spelling corrections of country names (logged, originals retained)
- Parsing of structured strings into typed columns (logged)

Not permitted on Layer 2:
- Dropping records
- Imputing missing values
- Changing numeric coordinates or azimuths
- Applying any analytical transformation (bearings, residuals, clusters)

**Layer 3 — Analytical products** (computed at runtime, never saved to `data/`):
Bearings, angular residuals, cluster assignments, hypothesis test results. All computed from Layer 2 at analysis time by package functions. Never baked into the shipped dataset.

## Rationale

- Keeping the raw file in the repo means reproducibility does not depend on Figshare availability.
- The three-layer separation makes the boundary between "what Gibson recorded" and "what qiblalab computed" explicit and auditable.
- Banning analytical transformations from Layer 2 prevents the common error of shipping pre-computed results as though they were primary data.

## Consequences

- `data-raw/qibla_data.R` is the single authoritative script that produces Layer 2 from Layer 1.
- Any future update to the Figshare dataset produces a new Layer 2 with a new audit log entry.
- `data/gibson_qibla.rda` is committed to version control (30 KB compressed); large derived outputs are not.
- The `download_qibla_data()` function in `R/` is for users who want to fetch the source independently; it does not replace `data-raw/qibla_data.R`.
